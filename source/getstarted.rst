Getting Started Hub

Welcome to the iNoCulator onboarding landing page. This section covers the architectural primitives of the platform ecosystem—guiding you through profile initialization, secure multifactor authentication handshakes, credential recoveries, and self-service registration exception handling.

--------------------------------------------------------------------------------

Platform Onboarding Matrices
================================

Select an active administrative track below to review step-by-step instructions:

.. grid:: 2
   :gutter: 3

   .. grid-item-card:: 👤 1. Account Provisioning
      :class-header: bg-light font-weight-bold

      Initialize a new, authorized engineering profile block inside the corporate user registry.
      
      * :doc:`Request Access <requestaccess>` — Submit your identity records for administrative audit.
      * :doc:`Invite User <inviteuser>` — Provision collaborator tokens from the Group Admin panel.
      * :doc:`Activate Account <activateaccount>` — Complete the time-locked email registration token verification.

   .. grid-item-card:: 🔐 2. Authentication Operations
      :class-header: bg-light font-weight-bold

      Pass through security gateways to load your active multi-die network canvases.
      
      * :doc:`Log In <login>` — Submit your registered identity credentials to the authentication layer.
      * :doc:`One-Time Pin (OTP) <otp>` — Fulfill two-factor verification parameters via secure code strings.
      * :doc:`Logout <logout>` — Gracefully terminate your browser session and flush localized cache blocks.

   .. grid-item-card:: 🛠️ 3. Credential Recovery
      :class-header: bg-light font-weight-bold

      Restore platform entry channels if you have lost your primary workspace credentials.
      
      * :doc:`Forgot Password <forgotpassword>` — Run self-service resets to nominate a clean account password.

   .. grid-item-card:: ⚠️ 4. Boundary Troubleshooting
      :class-header: bg-light font-weight-bold

      Identify and resolve validation warnings, registration exceptions, or access blocks.
      
      * :doc:`Expired Account <expiredaccount>` — License boundary resolution and renewal procedures.
      * :doc:`Suspended Account <suspendedaccount>` — Handling profile locks and administrative holds.
      * :doc:`Invalid Credentials <invalidcredentials>` — Resolving credential string mismatches.
      * :doc:`Duplicate Email <duplicateemail>` — Resolving email identity duplication conflicts.
      * :doc:`Expired Link <expiredlink>` — Re-triggering timed-out activation tokens.
